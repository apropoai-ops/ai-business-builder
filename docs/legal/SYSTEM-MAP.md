## ‏2. תשתיות

| ‏רכיב | ‏ספק | ‏מיקום | ‏תפקיד |
|---|---|---|---|
| ‏הרצת אפליקציה | Vercel | ‏ארה"ב / אירופה | Next.js serverless |
| ‏מסד נתונים | Supabase | ‏יפן — ap-northeast-1 | PostgreSQL 17.6 |

## ‏3. מערכות תוכנה

| ‏שכבה | ‏טכנולוגיה |
|---|---|
| ‏אפליקציה | Next.js 16.2.12 · React 19 · TypeScript |
| ‏גישה לנתונים | `@supabase/ssr` — ‏לקוח משתמש (RLS) · לקוח service-role (שרת בלבד) |
| ‏אבטחת דפדפן | CSP · HSTS · nosniff · frame-ancestors · Permissions-Policy |
| ‏הגבלת קצב | ‏מבוסס PostgreSQL — `rate_limits` + `bump_rate_limit` |
| ‏הצפנת אישורים | AES-GCM — `lib/services/integrations/credentials.ts` |
| ‏הגנת בוטים | Cloudflare Turnstile *(בנוי, ממתין למפתחות)* |

## ‏5. בקרת גישה

| ‏סוג גישה | ‏מנגנון |
|---|---|
| ‏בעל עסק | Supabase Auth → RLS ‏לפי `is_business_owner()` |
| ‏חבר צוות | `business_members` — ‏יורש הרשאות דרך אותה פונקציה |
| ‏לקוח קצה | ‏חשבון לקוח נפרד; גישה להזמנות שלו בלבד |
| ‏אנונימי | ‏קריאה בלבד לאתרים שפורסמו; כתיבה רק דרך פעולות מוגבלות-קצב |
| ‏מפעיל המערכת | ‏גישת ניהול ל-Vercel ול-Supabase — **מורשה גישה יחיד** |

‏פונקציות `SECURITY DEFINER` שנבדקו בפועל ואוכפות בעלות: `get_business_report`,
`next_invoice_number` (‏שתיהן זורקות `not authorized` למי שאינו בעלים).
