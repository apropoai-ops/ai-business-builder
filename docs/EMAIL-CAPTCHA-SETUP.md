## 1️⃣ Resend — אימות דומיין

### למה זה חוסם
`RESEND_API_KEY` **כבר מוגדר** בפרודקשן, אבל `RESEND_FROM` לא. בלי דומיין מאומת
Resend שולח מהכתובת הדיפולטית `onboarding@resend.dev`, שמותרת **רק לכתובת
הבעלים של החשבון**. בפועל זה אומר שכל אלה לא מגיעים ללקוחות שלך:

| מה שנשלח | מתי | הקובץ |
|---|---|---|
| תזכורת תור יום מראש + שעה מראש | cron כל 15 דק' | `lib/services/booking-reminders.service.ts` |
| אישור תור ללקוח | קביעת תור | `lib/services/booking-notify.ts` |
| התראת תור חדש לבעלים ולעובד | קביעת תור | `lib/services/booking-notify.service.ts` |
| ליד חדש מהאתר | שליחת טופס | `lib/services/public-site.ts` |
| אישור הזמנה + עדכון משלוח | תשלום / שינוי סטטוס | `lib/services/orders.service.ts` |
| הזמנת חבר צוות | שליחת הזמנה | `lib/services/members.service.ts` |

### צעדים

1. היכנס ל-[resend.com](https://resend.com) → **Domains** → **Add Domain** → הזן `apropo.business`.
2. Resend יציג 3 סוגי רשומות DNS: **MX** (לכתובת `send`), **TXT SPF**, ו-**TXT DKIM**.
3. הוסף אותן אצל מי שמנהל את ה-DNS של הדומיין. אם הדומיין נקנה דרך Vercel:
   **Vercel → Domains → apropo.business → DNS Records → Add**.
   העתק כל רשומה **בדיוק** — כולל ה-Name/Host המדויק. אל תוסיף את שם הדומיין
   לסוף ה-Name אם הממשק כבר מוסיף אותו אוטומטית (טעות נפוצה שגורמת ל-DKIM ליפול).
4. לחץ **Verify** ב-Resend. התפשטות DNS לוקחת בדרך כלל דקות, לפעמים עד 48 שעות.
5. אחרי שהדומיין ירוק — הוסף ב-Vercel משתנה סביבה חדש:

   | משתנה | ערך |
   |---|---|
   | `RESEND_FROM` | `AI Business Builder <noreply@apropo.business>` |

   הפורמט `"שם <כתובת>"` נתמך ומפוענח ב-`lib/services/email.service.ts`.
   כתובת בלבד (בלי שם) גם עובדת.
6. פרוס מחדש כדי שהמשתנה ייתפס:

```bash
npx vercel --prod --yes
```

### איך יודעים שזה עבד
- בממשק: **עסק → אינטגרציות → כרטיס "אימייל"** מציג סטטוס מוגדר.
- בפועל: קבע תור בדמו ובדוק שהאישור הגיע לכתובת שאינה שלך.
- בלוג: טבלת `email_log` מתעדת כל ניסיון שליחה (`sent` / `failed` / דילוג-ללא-מפתח).

### עלות
מסלול חינם: **3,000 מיילים בחודש**. מעבר לזה $20/חודש ל-50,000.
בהיקף שלך המסלול החינמי מספיק בקלות.

## 2️⃣ Cloudflare Turnstile — הגנת ספאם על הטפסים הציבוריים

### למה זה חשוב
`lib/captcha.ts` נמצא כרגע ב-**pass-through**: כל עוד `TURNSTILE_SECRET_KEY`
לא מוגדר, `verifyTurnstileToken` מחזיר `true` תמיד. כלומר כל טופס ציבורי —
לידים מהאתר, קביעת תורים, הרשמה לניוזלטר — פתוח לבוטים. ברגע שהמפתח מוגדר
המנגנון **נכשל סגור**: טוקן חסר או לא תקין נדחה, וגם תקלת רשת מול Cloudflare
נדחית ולא נותנת לספאם לחמוק.

### צעדים

1. הירשם ל-[cloudflare.com](https://cloudflare.com) (חינם, לא נדרש להעביר את ה-DNS אליהם).
2. בתפריט הצד → **Turnstile** → **Add widget**.
3. מלא:
   - **Widget name**: `apropo-business`
   - **Hostnames**: `apropo.business` ועוד שורה ל-`localhost` (לפיתוח מקומי)
   - **Widget Mode**: **Managed** (Cloudflare מחליט מתי להציג אתגר — הכי פחות חיכוך ללקוח)
4. קבל שני מפתחות והוסף אותם ב-Vercel:

   | משתנה | מקור | הערה |
   |---|---|---|
   | `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Site Key | ציבורי — מוטמע בדפדפן |
   | `TURNSTILE_SECRET_KEY` | Secret Key | **סודי** — שרת בלבד |

5. פרוס מחדש:

```bash
npx vercel --prod --yes
```

### איך יודעים שזה עבד
- הווידג'ט מופיע לבד בתחתית הטפסים (`components/public/turnstile-field.tsx`
  לא מרנדר כלום כשה-Site Key חסר).
- בממשק: **עסק → אינטגרציות → כרטיס "הגנת ספאם"** משנה סטטוס.
- שלח ליד מדפדפן אמיתי ובדוק שהוא נכנס ל-CRM.

> ⚠️ **חובה לבדוק שליחת טופס אמיתית מיד אחרי ההפעלה.** אם רק הסוד הוגדר בלי
> ה-Site Key, הדפדפן לא ישלח טוקן — והשרת ידחה **כל** ליד בשקט. שני המשתנים
> חייבים לעלות יחד.

### עלות
**חינם ללא הגבלה.** זה גם היתרון על reCAPTCHA וגם עדיף מבחינת פרטיות.
